# Window

## Use

Click the icon. The window scans the library. Opening it does not start or stop indexing.

**Start indexing** pauses NOMAD's file embedding and continues from the saved article. The reader opens the ZIM once, walks to that article, and keeps going from there. **Rescan** reads the library again. It does not pause NOMAD or start indexing. **Stop** ends the embed that is already running and keeps the last article that was fully saved. It does not delete the index. When the run started on Manual, unfinished files are not handed back to stock NOMAD. **Delete index** sits at the right end of the button row. You must type DELETE. Indexing does not start. ZIM files and uploads stay.

The header shows the package version beside **Index**, **Repair**, **Settings**, **Qdrant**, **Models**, and **About**. **Host system graphs** is a button. It shows CPU, memory, GPU, and video memory, plus a read graph and a write graph for each disk indexing uses and for the disk that holds the knowledge base. A folder on its own disk is its own graph. The blue line is read and the red line is write. A vertical bar sets that pane's width. Dragging it left wraps the Index controls, the Repair controls, and the log row so they stay visible, and the bar stops at the narrowest width those controls still fit. The window still asks for at most 480 by 280. If the window is already that small, the host side shrinks. Whether the pane is open, and that width, are remembered. **Order** and **Hide finished** sit on that header. The order is remembered. The header link opens the [Nomad TURBO Index repository](https://github.com/Vibe-Dragon/Nomad-TURBO-Index). **About** is its own page. It shows this Turbo version, states that this version was tested with Project NOMAD 1.35.2, and links to that repository and the [Project NOMAD repository](https://github.com/Crosstalk-Solutions/project-nomad). It names the author Vibe-Dragon, the MIT license, Copyright 2026, that these notes are updated when I get to it, and that I am not responsible if Turbo messes up an index.

**Qdrant** is the page beside Settings. It reads the knowledge-base collection when you open it. Storage is Float32 or Float16, and a Qdrant that reports version 1.20 or newer also lists Turbo16, Turbo8, and Turbo4. The quantization add-on and Graph on disk change the collection that is already there and keep the points. Changing the storage type asks you to type DELETE, removes the collection, and creates an empty one. Indexing does not start, and ingest stays on Manual. Until Apply is pressed, deleting the index still creates Float32. Hover each control for what it does. Reopen Turbo once so the open window shows the page.

**Models** is the page after Qdrant. It installs an Ollama library tag or a local GGUF, names each model in the assistant dropdown, and sets thinking, context, and sampling. A new model stays off the menu until Show in menu is turned on. Install, test, and delete wait while indexing is running. A menu name can still be saved. Opening Turbo writes the menu into the running chat page. A NOMAD update restores the stock menu until Turbo is opened again. Reopen Turbo once so the open window shows the page.

The file list is the part that grows. On Index, the library bar under the list is the full width of the list. The optimization bar sits above the list and appears when indexing is waiting on a segment rewrite. The stats line is under the library bar. **Start indexing**, **Stop**, **Rescan**, and **Stay on** are one group of buttons. **Measure** and **Then index** are the two halves of one button. **OCR** is Low, Medium, or High. **Parallel OCR**, **OCR workers**, and **ZIM documents** are on the Settings page. **OCR workers** is a slider and a number. The top leaves two threads free, and the next page uses that number. **Parallel OCR** is experimental and off until it is turned on. **ZIM documents** is off until it is turned on. **Auto**, the chunk field, **Recommended**, and the embed-server count are the embed-batch group. **Delete index** stays apart at the end. When the page is narrow those groups wrap, and the list gives up that height. The chunk count is the number in the field. The count beside **Recommended** is how many embed servers are running. Card memory is on the host graphs. At the default window size, with the log open, each file list is at least half its page. Extra height goes to the list. Hover any button, column heading, progress bar, or those lines for what they do.

The Qdrant line sits under the page switch. The line under it says what Turbo is doing when the file list is still. Green is indexing or idle. Blue is a pause that is still working, including Stop while it updates the knowledge-base records. Amber means leave Qdrant running. Red needs attention. **Start indexing**, **Delete index**, **Scan**, and **Start repair** stay off until the Qdrant line says `Qdrant is ready for changes.` **Rescan** does not wait.

The window edges resize the whole window. The smallest size it asks for is 480 by 280. If the controls need more height than that, the window stays tall enough to keep them on screen. That size and its place on the screen are saved, and a maximized window opens maximized. The controls stay under the file list, against the bar above the log. That bar changes the list height. The log row stays against the other side of the bar. Whether the log is open, and that bar, are remembered. Column edges resize. Those positions are remembered. Blue names are ZIM files and amber names are uploads. That note is on the File heading, and on the Index status line's tip. Repair's longer instructions are on the repair status tip.

If Turbo dies while the embed queue is paused, the next time the window opens it puts the ingest policy back and resumes NOMAD embedding. If a repair delete may still be running, embedding stays paused. `nomad-turbo recover` does the same thing.

**Stay on** keeps Turbo in control when the queue is empty, so files that arrive later are indexed by Turbo. The button's tip is the sentence "Stay on after the last file, and index new files as they arrive." Off, which is the default, Turbo stops and the ingest policy returns to the value found at Start. When the run started on Manual, stock NOMAD does not start embedding.

Closing the window while a run is going hides it to the tray. The tray menu can show the window or stop the run. The tray icon is the plain logo when idle, the logo on fire while indexing, and blue while a repair is running. Clicking the desktop icon brings the window back. It does not start or stop the run.

## Index

The Index page is the library list. **Queue**, at the right of the header, opens the embed queue and the OCR queue beside this window.

- **File.** Blue names are ZIM files. Amber names are uploads. `kb_uploads` and `zim` are folders. Click the arrow to open or close one. They start closed. A closed folder does not keep its files in the list. Hover a row for the full path. A red asterisk to the left of the name means that file is prioritized. The folder-tree row of a file that is in progress carries a tree mark the other file rows do not. The pinned rows above the tree name the file being indexed, and the file being read when Parallel OCR is on and CPU OCR overlaps the GPU. The tree mark goes away when that file is no longer in progress.
- **File type.** zim, pdf, docx, epub, txt, md, rtf, an image extension such as jpg or png, or folder.
- **Size.** The file on disk.
- **Status.** Waiting, Waiting OCR, indexing, indexed, partial, failed, or needs NOMAD. Waiting OCR is a ZIM whose pages are stored while PDFs from it are still in the OCR queue. That row stays in the list. While a file is in progress the status names the pass: HTML, text, OCR, or OCR text.
- **Progress.** While a file is being embedded, the faded bar is chunks that already have vectors and the solid bar is what is saved in the knowledge base. The label is the saved percent, then the processed percent. A ZIM fills the solid bar once for HTML, again for other text, and again for OCR. While OCR is reading, this is one bar for the pages read.
- **Articles.** While a file is being indexed, articles saved in the knowledge base and how many are left. During a text or OCR pass, the right number is what that pass has left. Other rows show articles stored and the total when it is known. While OCR is reading, this is pages read and pages in the file.
- **art/min.** Articles per minute whose vectors have come back, for the file being indexed. This moves before those articles are saved. While OCR is reading, this is pages per minute. Other rows stay blank.
- **Chunks.** Embedded pieces stored for this file. A long page is many chunks.
- **chk/s.** Chunks per second that have received vectors, for the file being indexed. This moves while an embed call is still running.
- **ETA.** Time left for this file. After Measure, a sampled file keeps that ETA. While OCR is reading, the time left follows the page rate. When nothing has been saved yet, the file being indexed uses articles whose vectors have come back.

**Order** chooses which unfinished file comes next. The file already in progress keeps going. Prioritized files come next, in that order. Text that has finished OCR comes after those prioritized files and before the other unfinished files. The list itself is the `kb_uploads` and `zim` folder tree, with folders before files and both in name order. The file being indexed is also pinned above that tree and stays there while the tree scrolls. When Parallel OCR is on and CPU OCR overlaps GPU indexing, the file being read is pinned there too. The GPU finishes the file it is on before it indexes a read that has just finished. Finished reads stay in memory until the text reaches about a quarter of system memory, and further finished reads wait in a temporary file. **Hide finished** takes indexed files out of the tree, and hides a folder that only held those files. Right-click a file for **Index now**, to set or clear priority, or for **Details**. Details shows the file's size, location on disk, download date, ZIM date, article and chunk counts, slowest and fastest speeds, the last measured ETA, and whether it is prioritized. Those facts are saved and come back the next time Turbo opens. A file that leaves the library is forgotten. Priority comes back with them. **Measure** indexes each file that has not been started for about five minutes. A file that already has progress keeps its ETA and is left alone. It then resumes a run that was already going, or stops the way **Stop** does when Measure started from idle. **Then index** does nothing until a measurement is already going. It does not start indexing and it does not start a measurement. During a measurement it arms that same pass to keep indexing after the samples, including a pass that started while idle, without restarting the pass or clearing the samples already taken. The half shows that it took effect. **Measure** stays clickable again once the run is idle.

The library bar under the list is the whole library, weighed by file size, and the time left for what remains. The file being indexed is the row above the tree, so that bar does not repeat its name. **Embed batch** is the chunk field in the embed-batch group, with **Auto**, **Recommended**, and the server count. **Delete index** stays apart at the end. Typing a count during a run changes the next embed call. The label beside **Recommended** says how many embed servers are running.

An optimization bar appears above the file list while indexing is paused so a segment can be rewritten. Each new pause starts that bar's clock over. Qdrant does not report how far the in-memory build is, so the bar moves without a percent. The stats line counts articles per minute, chunks per minute, skipped pages, and bad pages. Skipped pages had no text. Bad pages could not be read or parsed. A long page is indexed in full.

The file being indexed stays in its own row above the folder tree. Column headings sit on that row. Drag a column edge to resize it. That width is remembered, and the tree below uses the same edges. Extra space stays on the last column.
